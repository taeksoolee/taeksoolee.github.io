Backend · Architecture

Hono 헥사고날 아키텍처 가이드

비즈니스 로직을 Hono·Drizzle·Zod 로부터 떼어 놓고, Hono RPC 로 프론트엔드까지 CodeGen 없이 타입을 잇는 구조.

2026-10-14 Hono · Drizzle ORM · Zod · TypeScript

Contents

    1. 아키텍처 개요

    기능 중심 헥사고날 아키텍처(Feature-based Hexagonal Architecture)를 채택해, 비즈니스 로직(Domain Core)을 외부 프레임워크와 DB 기술(Hono, Drizzle, Zod 등)로부터 격리합니다.

    또한 Hono RPC 로 백엔드 라우터의 타입을 프론트엔드에 그대로 넘겨, 별도의 CodeGen 없이 요청·응답 타입을 끝에서 끝까지 공유합니다. 

            [ Client (React / Next.js) ]
                     │
                     ▼  Hono RPC / HTTP
┌──────────────────────────────────────────────────────┐
│  Inbound Adapter   (Hono Routes + Zod Validator)     │
│        │                                             │
│        ▼                                             │
│  ┌────────────────────────────────────────────────┐  │
│  │  Domain Core   (Use Cases · Entities · Ports)  │  │
│  │  - no external dependencies                    │  │
│  └───────────────────────┬────────────────────────┘  │
│                          │ Outbound Port (interface) │
│                          ▼                           │
│  Outbound Adapter  (Drizzle ORM / External APIs)     │
└──────────────────────────────────────────────────────┘

    2. 디렉토리 구조

    3. 핵심 규칙과 의존성 원칙

    1. domain/ 은 순수하게.
      • hono, drizzle-orm, zod 등 외부 npm 패키지를 import 하지 않습니다.
      • 순수 TypeScript 로 엔티티·에러·유즈케이스와 자기 도메인의 포트 인터페이스만 정의합니다.
    2. 의존성은 한 방향으로.
      • Adapters → Domain (Ports · Use Cases) → Entities
      • Domain 이 Adapters 나 Shared 를 참조하는 것은 금지입니다.
      • Inbound Adapter 도 Outbound Adapter 를 직접 알지 않습니다. 둘을 묶는 일은 Composition Root(users.module.ts) 만 합니다.
    3. Feature 끼리는 독립적으로.
      • features/users 는 features/auth 의 adapters 를 직접 참조하지 않고, 필요하면 domain/ports 인터페이스를 통해 연결합니다.

    4. 단계별 구현 예시

    Step 1. Entity · Error · Port 정의 (domain/)

    src/features/users/domain/user.entity.ts
    export interface User {
  id: string;
  email: string;
  name: string;
  createdAt: Date;
}

export type NewUser = Omit<User, 'id' | 'createdAt'>;
    src/features/users/domain/user.errors.ts
    export class UserAlreadyExistsError extends Error {
  constructor(readonly email: string) {
    super(`User already exists: ${email}`);
    this.name = 'UserAlreadyExistsError';
  }
}
    src/features/users/domain/ports/user-repository.port.ts
    import type { NewUser, User } from '../user.entity';

export interface UserRepositoryPort {
  save(user: NewUser): Promise<User>;
  findByEmail(email: string): Promise<User | null>;
}

    Step 2. Use Case 구현 (domain/use-cases/)

    src/features/users/domain/use-cases/create-user.use-case.ts
    import type { User } from '../user.entity';
import type { UserRepositoryPort } from '../ports/user-repository.port';
import { UserAlreadyExistsError } from '../user.errors';

export class CreateUserUseCase {
  constructor(private readonly userRepository: UserRepositoryPort) {}

  async execute(email: string, name: string): Promise<User> {
    const existing = await this.userRepository.findByEmail(email);
    if (existing) {
      throw new UserAlreadyExistsError(email);
    }

    return this.userRepository.save({ email, name });
  }
}

    Step 3. Outbound Adapter 구현 (adapters/outbound/)

    src/features/users/adapters/outbound/persistence/user.schema.ts
    import { pgTable, text, timestamp, uuid } from 'drizzle-orm/pg-core';

export const usersTable = pgTable('users', {
  id: uuid('id').primaryKey().defaultRandom(),
  email: text('email').notNull().unique(),
  name: text('name').notNull(),
  createdAt: timestamp('created_at').notNull().defaultNow(),
});
    src/features/users/adapters/outbound/persistence/drizzle-user.repository.ts
    import { eq } from 'drizzle-orm';
import { db } from '../../../../../shared/db/client';
import type { NewUser, User } from '../../../domain/user.entity';
import type { UserRepositoryPort } from '../../../domain/ports/user-repository.port';
import { usersTable } from './user.schema';

// DB 행 → 도메인 엔티티. 테이블 컬럼이 바뀌어도 도메인은 그대로 둔다.
const toDomain = (row: typeof usersTable.$inferSelect): User => ({
  id: row.id,
  email: row.email,
  name: row.name,
  createdAt: row.createdAt,
});

export class DrizzleUserRepository implements UserRepositoryPort {
  async findByEmail(email: string): Promise<User | null> {
    const [row] = await db.select().from(usersTable).where(eq(usersTable.email, email));
    return row ? toDomain(row) : null;
  }

  async save(user: NewUser): Promise<User> {
    const [row] = await db.insert(usersTable).values(user).returning();
    return toDomain(row);
  }
}

    Step 4. Inbound Adapter 구현 (adapters/inbound/)

    Hono RPC 주의

    Hono RPC 가 프론트엔드로 타입을 넘기려면 new Hono().get().post() 처럼 메서드 체이닝을 유지해야 합니다. app.get(...) 을 문장으로 끊어 쓰면 타입 추론이 끊깁니다.

    src/features/users/adapters/inbound/http/users.dto.ts
    import { z } from 'zod';

export const createUserSchema = z.object({
  email: z.string().email(),
  name: z.string().min(2),
});

    라우터는 구현체를 직접 만들지 않고 유즈케이스를 인자로 받는 팩토리로 둡니다. 도메인 에러는 여기서 HTTP 상태 코드로 바꿉니다. 이렇게 하면 409 응답도 RPC 타입에 실려 프론트엔드에서 분기할 수 있습니다.

    src/features/users/adapters/inbound/http/users.routes.ts
    import { Hono } from 'hono';
import { zValidator } from '@hono/zod-validator';
import type { CreateUserUseCase } from '../../../domain/use-cases/create-user.use-case';
import { UserAlreadyExistsError } from '../../../domain/user.errors';
import { createUserSchema } from './users.dto';

export const createUserRoutes = (createUser: CreateUserUseCase) =>
  new Hono()
    .post('/', zValidator('json', createUserSchema), async (c) => {
      const { email, name } = c.req.valid('json');
      try {
        const user = await createUser.execute(email, name);
        return c.json(user, 201);
      } catch (err) {
        if (err instanceof UserAlreadyExistsError) {
          return c.json({ error: 'USER_ALREADY_EXISTS' as const }, 409);
        }
        throw err; // 예상하지 못한 에러는 전역 onError 로
      }
    });

    Step 5. Composition Root (users.module.ts)

    포트와 구현체를 실제로 연결하는 곳은 여기 하나입니다. DB 를 바꾸거나 테스트용 구현체를 끼울 때도 이 파일만 고칩니다.

    src/features/users/users.module.ts
    import { CreateUserUseCase } from './domain/use-cases/create-user.use-case';
import { DrizzleUserRepository } from './adapters/outbound/persistence/drizzle-user.repository';
import { createUserRoutes } from './adapters/inbound/http/users.routes';

const userRepository = new DrizzleUserRepository();
const createUserUseCase = new CreateUserUseCase(userRepository);

export const userRoutes = createUserRoutes(createUserUseCase);

    Step 6. 진입점 · 전역 에러 핸들러 · AppType export

    에러 처리는 미들웨어가 아니라 onError

    Hono 는 핸들러에서 던진 에러를 내부에서 잡아 app.onError 로 넘깁니다. 그래서 app.use('*', ...) 미들웨어 안에서 try { await next() } catch 로 감싸도 잡히지 않습니다.

    src/shared/http/error-handler.ts
    import type { ErrorHandler } from 'hono';
import { HTTPException } from 'hono/http-exception';

export const errorHandler: ErrorHandler = (err, c) => {
  if (err instanceof HTTPException) {
    return err.getResponse();
  }
  console.error(err);
  return c.json({ error: 'INTERNAL_SERVER_ERROR' }, 500);
};
    src/index.ts
    import { Hono } from 'hono';
import { userRoutes } from './features/users/users.module';
import { errorHandler } from './shared/http/error-handler';
import { loggerMiddleware } from './shared/middleware/logger.middleware';

const app = new Hono();

// 1. 공통 미들웨어 · 에러 핸들러
app.use('*', loggerMiddleware);
app.onError(errorHandler);

// 2. 피처별 라우터 연결 (체이닝 결과를 변수로 받아야 타입이 남는다)
const routes = app.route('/api/users', userRoutes);

// 3. 서버 실행용 기본 export
export default app;

// 4. 프론트엔드 공유용 — 값이 아니라 타입만 내보낸다
export type AppType = typeof routes;

    5. 프론트엔드 연동 (Hono RPC Client)

    프론트엔드는 백엔드의 실행 코드가 아니라 AppType 타입만 가져옵니다. import type 이라 번들에는 백엔드 코드가 한 줄도 들어가지 않습니다. (모노레포처럼 프론트엔드에서 백엔드 소스 경로가 보이는 구성을 가정합니다.)

    client/src/lib/api-client.ts
    import { hc } from 'hono/client';
import type { AppType } from '../../../backend/src/index';

export const client = hc<AppType>('http://localhost:3000');

export async function submitForm() {
  const res = await client.api.users.$post({
    json: { email: 'user@example.com', name: 'Hong' },
  });

  if (res.status === 409) {
    const { error } = await res.json(); // 'USER_ALREADY_EXISTS'
    return;
  }

  if (res.ok) {
    const data = await res.json(); // { id, email, name, createdAt } 로 추론
    console.log(data.id, new Date(data.createdAt));
  }
}

    Date 는 string 으로 온다

    응답은 JSON 을 거치므로 createdAt: Date 는 클라이언트에서 string 으로 추론됩니다. 날짜로 쓰려면 new Date(data.createdAt) 처럼 직접 변환합니다.

    6. 테스트 전략

    Use Case 단위 테스트

    도메인이 포트에만 의존하므로 DB 나 Hono 없이 인메모리 구현체 하나로 바로 검증할 수 있습니다. 이 구현체는 testing/ 에 두고 단위·통합 테스트에서 함께 씁니다.

    src/features/users/testing/in-memory-user.repository.ts
    import type { NewUser, User } from '../domain/user.entity';
import type { UserRepositoryPort } from '../domain/ports/user-repository.port';

export class InMemoryUserRepository implements UserRepositoryPort {
  private users: User[] = [];

  async findByEmail(email: string) {
    return this.users.find((u) => u.email === email) ?? null;
  }

  async save(input: NewUser) {
    const user = { ...input, id: crypto.randomUUID(), createdAt: new Date() };
    this.users.push(user);
    return user;
  }
}
    src/features/users/domain/use-cases/create-user.use-case.test.ts
    import { describe, expect, it } from 'vitest';
import { InMemoryUserRepository } from '../../testing/in-memory-user.repository';
import { UserAlreadyExistsError } from '../user.errors';
import { CreateUserUseCase } from './create-user.use-case';

describe('CreateUserUseCase', () => {
  it('같은 이메일로 두 번 가입하면 UserAlreadyExistsError', async () => {
    const useCase = new CreateUserUseCase(new InMemoryUserRepository());

    await useCase.execute('a@example.com', 'Hong');

    await expect(useCase.execute('a@example.com', 'Kim'))
      .rejects.toBeInstanceOf(UserAlreadyExistsError);
  });
});

    라우트 통합 테스트

    라우터가 유즈케이스를 인자로 받기 때문에 테스트에서는 인메모리 구현체를 끼우면 됩니다. app.request() 는 서버를 띄우지 않고 메모리 안에서 요청을 처리합니다.

    src/features/users/adapters/inbound/http/users.routes.test.ts
    import { describe, expect, it } from 'vitest';
import { CreateUserUseCase } from '../../../domain/use-cases/create-user.use-case';
import { InMemoryUserRepository } from '../../../testing/in-memory-user.repository';
import { createUserRoutes } from './users.routes';

const post = (app: ReturnType<typeof createUserRoutes>, body: unknown) =>
  app.request('/', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });

describe('POST /api/users', () => {
  const app = createUserRoutes(new CreateUserUseCase(new InMemoryUserRepository()));

  it('생성 201 → 중복 409', async () => {
    const body = { email: 'a@example.com', name: 'Hong' };
    expect((await post(app, body)).status).toBe(201);
    expect((await post(app, body)).status).toBe(409);
  });

  it('검증 실패는 400', async () => {
    expect((await post(app, { email: 'not-an-email', name: 'H' })).status).toBe(400);
  });
});
